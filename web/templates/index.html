Course Recommendation & Allocation System — Technical Architecture

The system implements a pure relational MySQL DBMS architecture with zero procedural logic in the application tier. Recommendation shortlisting is computed declaratively via SQL Views with interest tag matching, while seat allocation is strictly governed by idempotent stored procedures and ACID-compliant trigger-enforced capacity invariants.

Step 1

Course Preferences

student_course_preferences

Students explore interest tracks in the Course Catalog and submit 2 to 5 ranked elective choices.

Step 2

Primary Allocation Engine

allocate_courses(course_id)

Deterministic 4-tier ranking allocates seats up to max_allocations. Overflows are placed in WAITLIST.

Step 3

Merit Fallback Sweep

allocate_unallotted_fallback()

If choices are full or ineligible, unallotted students are assigned to the best available elective based on CGPA.

Deterministic Multi-Tier Tie-Breaking Hierarchy

The stored procedure executes window function ROW_NUMBER() OVER (...) to order all competing applicants. Rank numbers are uniquely assigned without shared positions:

1

Academic Merit

s.cgpa DESC

Highest CGPA always gets first priority for elective seats.

2

Student Preference

scp.preference_rank ASC

Student who ranked the subject higher wins seat on CGPA tie.

3

Timestamp Audit

scp.submitted_at ASC

Earlier submission wins tie (first-come, first-served audit).

4

Deterministic Key

s.student_id ASC

Surrogate key tie-break guarantees reproducible integer rank.

Documented Institutional Rule: Dual-Status Behavior

A student can be WAITLISTED in an oversubscribed course of higher preference and subsequently obtain an ALLOTTED seat in a lower-preference course evaluated later in the cycle. This guarantees students are not denied an elective seat simply because their first choice reached maximum capacity.

Database Triggers & Stored Procedures Specification

trg_before_allocation_insert (BEFORE INSERT TRIGGER)

Fires before any row is inserted into allocations. If NEW.status = 'ALLOTTED' and current_allocations >= max_allocations, it raises SIGNAL SQLSTATE '45000' ('Course full: cannot allot'). Enforces capacity invariants even against manual direct SQL insertions.

trg_after_allocation_insert (AFTER INSERT TRIGGER)

Fires after an insert into allocations. If NEW.status = 'ALLOTTED', it automatically increments courses.current_allocations by 1, guaranteeing transactional synchronization of seat counters.

allocate_courses(IN p_course_id INT) (STORED PROCEDURE)

Calculates available seats (max_allocations - current_allocations). Selects eligible students meeting cutoff without an existing allotment, ranks them via ROW_NUMBER(), inserts ALLOTTED up to capacity, WAITLISTED for excess, and REJECTED for below-cutoff applicants.

run_full_allocation_cycle() (STORED PROCEDURE)

Ensures total idempotency: deletes existing allocations, resets courses.current_allocations = 0, iterates through courses calling allocate_courses(), and finally executes allocate_unallotted_fallback() to place any unallotted students into best-fit remaining seats by CGPA.

allocate_unallotted_fallback() (STORED PROCEDURE)

Identifies students without an allotment and evaluates available seats across all courses. Assigns the highest-tier eligible elective (ORDER BY min_cgpa_required DESC, credits DESC) based on academic merit.

Relational Schema Definition Summary

students

(student_id PK AI, name, email UNIQUE, semester, department, cgpa CHECK 0.00..10.00)

courses

(course_id PK AI, course_code UNIQUE, course_name, credits CHECK>0, min_cgpa_required, max_allocations, current_allocations, department)

course_tags

(tag_id PK AI, tag_name UNIQUE)

course_tag_map

(course_id FK, tag_id FK, PK(course_id, tag_id)) ON DELETE CASCADE

student_tag_preferences

(student_id FK, tag_id FK, preference_rank CHECK>0, PK(student_id, tag_id)) ON DELETE CASCADE

student_course_preferences

(student_id FK, course_id FK, preference_rank CHECK>0, submitted_at, PK(student_id, course_id)) ON DELETE CASCADE

allocations

(allocation_id PK AI, student_id FK, course_id FK, status ENUM('ALLOTTED','WAITLISTED','REJECTED'), allocated_at, UNIQUE(student_id, course_id)) ON DELETE CASCADE
