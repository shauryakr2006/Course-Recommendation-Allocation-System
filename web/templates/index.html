Deterministic Multi-Tier Allocation Engine

The allocation engine is executed by CALL run_full_allocation_cycle(); which loops over all courses via cursor and invokes allocate_courses(course_id). Ties are resolved strictly using window function ROW_NUMBER() across four hierarchical criteria:

1

Academic Merit

s.cgpa DESC

Highest CGPA always gets first priority for elective seats.

2

Student Preference

scp.preference_rank ASC

Student who ranked the subject higher wins seat on CGPA tie.

3

Timestamp Audit

scp.submitted_at ASC

Earlier submission wins tie (first-come, first-served audit).

4

Deterministic Key

s.student_id ASC

Surrogate key tie-break guarantees reproducible integer rank.

Documented Institutional Rule: Dual-Status Behavior

A student can be WAITLISTED in an oversubscribed course of higher preference and subsequently obtain an ALLOTTED seat in a lower-preference course evaluated later in the cycle. This guarantees students are not denied an elective seat simply because their first choice reached maximum capacity.

Relational Schema Definition Summary

students

(student_id PK AI, name, email UNIQUE, semester, department, cgpa CHECK 0.00..10.00)

courses

(course_id PK AI, course_code UNIQUE, course_name, credits CHECK>0, min_cgpa_required, max_allocations, current_allocations, department)

course_tags

(tag_id PK AI, tag_name UNIQUE)

course_tag_map

(course_id FK, tag_id FK, PK(course_id, tag_id)) ON DELETE CASCADE

student_tag_preferences

(student_id FK, tag_id FK, preference_rank CHECK>0, PK(student_id, tag_id)) ON DELETE CASCADE

student_course_preferences

(student_id FK, course_id FK, preference_rank CHECK>0, submitted_at, PK(student_id, course_id)) ON DELETE CASCADE

allocations

(allocation_id PK AI, student_id FK, course_id FK, status ENUM('ALLOTTED','WAITLISTED','REJECTED'), allocated_at, UNIQUE(student_id, course_id)) ON DELETE CASCADE
